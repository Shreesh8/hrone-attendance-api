# REVIEW.md

Defects found in the starter `app/main.py`, and how each was fixed.

| #   | Where                               | What is wrong                                                                                                                                                                                                       | How you'd notice it                                                                                                                                  | Fix                                                                                                     |
| --- | ----------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| 1   | `compute_late_minutes`              | Grace check runs after flooring: `int(secs/60) > 10`, so 09:40:01 gives minutes=10, not `> 10`, and returns 0 (R2 says 10).                                                                                         | Punch in at 09:40:01 on a 09:30 shift: expected `late_minutes` 10, got 0.                                                                            | Compare **seconds**: `secs > 600`, then `secs // 60`.                                                   |
| 2   | `compute_late_minutes`              | `punch_in.replace(hour=..)` anchors shift start to the punch's own calendar day, in whatever zone the datetime is in (naive/server-local, not IST).                                                                 | Server in UTC: 09:45 IST punch is 04:15 UTC, so "late" is compared with 09:30 UTC.                                                                   | Anchor on the IST attendance date: `ist_at(date, shift_start)`.                                         |
| 3   | `compute_late_minutes` / `punch_in` | Overnight shifts ignored (R1). A 00:30 punch on a 22:00-06:00 shift is dated the next day and is negative-late.                                                                                                     | EMP with 22:00-06:00, punch 00:30: record dated the 7th, `late_minutes` 0 instead of 150 on the 6th.                                                 | `attendance_date()` moves pre-`shift_end` punches to the previous day.                                  |
| 4   | `punch_in`                          | `datetime.fromtimestamp(ms/1000)` and `datetime.now()` use server-local time and produce naive datetimes. `.date()` is not the IST date; Mongo stores naive values as UTC, so instants shift.                       | Run the server in a non-IST zone; the record date is wrong near midnight IST.                                                                        | UTC-aware datetimes everywhere (`tz_aware=True`), converted to IST only for dates and shift maths.      |
| 5   | `punch_in`                          | `punched_at` is `Optional[int]` with no range check, and `if body.punched_at` treats 0 as "missing". Seconds, floats, strings and out-of-range numbers are accepted or misread. Sub-second part not truncated (R1). | `punched_at: 1783312500` (seconds) is accepted and lands in 1970.                                                                                    | `StrictInt` with 1e11 to 4.1e12 bounds, `None` check, truncate to whole seconds.                        |
| 6   | `punch_in`                          | Unknown employee: `emp` is `None`, so `emp["shift_start"]` raises TypeError -> 500.                                                                                                                                 | POST with `emp_code: "NOPE"`.                                                                                                                        | `get_employee()` raises 404.                                                                            |
| 7   | `punch_in` / `PunchInIn`            | `status` is a free string: `ABSENT`, `LEAVE` or `"banana"` are accepted.                                                                                                                                            | POST with `status: "ABSENT"`.                                                                                                                        | `Literal["PRESENT","WFH","ON_DUTY"]` -> 422.                                                            |
| 8   | `punch_in`                          | Check-then-insert race and no unique index: two simultaneous requests both pass `find_one` and both insert.                                                                                                         | Fire 10 parallel punch-ins; several return 201 and duplicate documents exist.                                                                        | Unique index `(emp_code, date)` created at startup; `DuplicateKeyError` -> 409.                         |
| 9   | `punch_in` response                 | Returns `id` (the ObjectId) and raw datetimes; the contract has no id and wants epoch ms.                                                                                                                           | Response contains `"id"` and non-integer `punch_in`.                                                                                                 | `serialize_record()` drops `_id` and converts to epoch ms.                                              |
| 10  | `compute_work_hours`                | Python `round()` is banker's rounding on a float, not half-up (R4). Not truncated to seconds.                                                                                                                       | 16218 s = 4.505 h should be 4.51.                                                                                                                    | `Decimal` quantize with `ROUND_HALF_UP` on integer seconds.                                             |
| 11  | `compute_overtime`                  | No 30-minute minimum (R3): any positive minute counts. The shift end is always placed on the same date, so an overnight shift (22:00-06:00) gets the wrong end time.                                                | Punch out 10 minutes after shift end: returns 10, should be 0. Overnight shift punching out at 06:40 gets a large negative/zero value instead of 40. | Floor the minutes, count them only if >= 30, and put the shift end on date + 1 for overnight shifts.    |
| 12  | `list_attendance`                   | Loads the **whole collection** into memory, sorts in Python, slices in Python. Sort has no `emp_code` tie-break.                                                                                                    | 100k records: slow, large memory.                                                                                                                    | Server-side `find().sort().skip().limit()` backed by indexes; `count_documents` for the total.          |
| 13  | `list_attendance`                   | No validation: `page=0`, negative or huge `page_size`, bad dates, `date_from > date_to`, unknown `status` all pass through.                                                                                         | page=0 makes the Python slice docs[-20:0]; `status=foo` returns an empty list instead of 422.                                                        | `Query(ge/le)`, date parsing, ordering check, `Literal` status -> 422.                                  |
| 14  | `list_attendance`                   | Leaks `id`, returns raw datetimes, and does not apply defaults for legacy records missing `half_day`/`history`.                                                                                                     | List a legacy sample record.                                                                                                                         | Same `serialize_record()` as other endpoints.                                                           |
| 15  | `list_employees`                    | `skip = page * page_size` is off by one page: page 1 skips the first page.                                                                                                                                          | `GET /employees?page=1` misses the first 20 employees.                                                                                               | `(page - 1) * page_size`.                                                                               |
| 16  | `list_employees`                    | `total` counts the whole collection, ignoring the department filter; no sort order.                                                                                                                                 | `?department=Eng` returns 3 items and `total` = 500.                                                                                                 | `count_documents(q)` with the same filter; sort by `emp_code`.                                          |
| 17  | `create_employee`                   | No validation (emp_code format, HH:MM, `shift_start == shift_end`, email, date), check-then-insert race, naive local `created_at` returned as a datetime.                                                           | Two parallel creates; `shift_start: "25:99"`.                                                                                                        | Pydantic constraints, unique index + `DuplicateKeyError` -> 409, UTC `created_at` returned as epoch ms. |
| 18  | `health`                            | Always returns ok, even when MongoDB is down.                                                                                                                                                                       | Stop MongoDB; `/health` still 200.                                                                                                                   | Ping Mongo; 503 on failure.                                                                             |
| 19  | module setup                        | `MongoClient` without `tz_aware` returns naive datetimes; no indexes created anywhere.                                                                                                                              | Every date comparison and query is a COLLSCAN.                                                                                                       | `tz_aware=True`; idempotent `ensure_indexes()` in the lifespan hook.                                    |

**Looked at and decided fine:** `load_dotenv()` (it does not override real environment variables, which is what the contract needs); `doc.pop("_id")` after `insert_one` (needed because PyMongo mutates the dict); synchronous `def` endpoints (FastAPI runs them in a thread pool and PyMongo's client is thread-safe).
